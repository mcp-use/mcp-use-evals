The decisive wrong turn was placing the server at root `index.ts` rather than a conventional `src/server.ts` or `src/index.ts`; the produced entry is `index.ts` with `export default server;`. This went unnoticed because the SDK accepted it locally: `[mcp-use] built index.ts + views (incident-detail, incident-list) → .mcp-use/build/index.js`, and the agent concluded, `Built the deterministic TypeScript MCP Apps incident console.`

With no scaffold or skill, the agent relied heavily on package inspection, first running `npm view mcp-use@2.0.4 ...`, then reading `node_modules/mcp-use/README.md`, declarations such as `node_modules/mcp-use/dist/server.d.ts`, and grepping for `useToolContext` and `outputTemplate|view|resourceUri`. That discovery process consumed several calls before implementation.

Dependency compatibility caused an avoidable detour: the agent initially installed `zod@3`, then changed course with `npm install zod@4`. View typing still resolved outputs as `{}`, producing repeated errors such as `Property 'id' does not exist on type '{}'` and `Property 'incidents' does not exist on type '{}'`. Even after `npx mcp-use typecheck` generated `mcp-env.d.ts`, the same errors remained. The eventual workaround used assertions rather than inferred SDK types: `context.toolOutput as typeof fallbackIncident` in `views/incident-detail/view.tsx` and `context.toolOutput as ListOutput` in `views/incident-list/view.tsx`.

The default npm scaffold also fought the runtime: `npm init -y` created `"type": "commonjs"`, after which start failed with `Cannot use import statement outside a module`. The agent had to modify `package.json` before start worked.

Verification itself had minor command-construction friction. The first Node assertion script failed at `file://[eval1]:1`, requiring a second nearly identical invocation before yielding `Verified: 2 tools, 2 readable MCP App resources, and correct per-tool view URIs.` Despite thorough wire-level verification, it never checked whether the external workflow required one of the expected `src/` entry paths.
