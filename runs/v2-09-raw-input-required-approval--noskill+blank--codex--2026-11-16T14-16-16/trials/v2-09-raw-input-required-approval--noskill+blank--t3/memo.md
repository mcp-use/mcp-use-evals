The agent relied heavily on installed package internals rather than external docs, first searching `node_modules/mcp-use` with `rg -n "inputRequired|inputResponse|acceptedContent|streamable|HTTP|http"` and then inspecting declarations under `node_modules/@modelcontextprotocol/server/dist`. This was productive for discovering helper and `listen` API shapes, but contributed to a relatively long exploration.

The first implementation used an incompatible Zod release and failed typechecking three times with errors such as `Property 'jsonSchema' is missing`. The fix was an extra dependency change, `npm install zod@'^4.1.0'`, after which `npx tsc --noEmit` passed. This version requirement was not caught during initial dependency setup.

Manual HTTP verification caused substantial protocol-discovery friction. The agent first mixed a modern header with a legacy handshake and received `an initialize request (legacy handshake) was sent with a modern MCP-Protocol-Version header`. Subsequent attempts discovered requirements one error at a time: `the required Mcp-Method header is absent`, then `the required Mcp-Name header is absent`, then `the request's client capabilities do not declare the required capability`. Only after adding `MCP-Method`, `MCP-Name`, and `"elicitation":{"form":{}}` did the request succeed. The agent investigated these details by repeatedly grepping generated SDK declarations and runtime files, including `RequestMetaEnvelopeSchema` and `InputResponseRequestParamsSchema`, indicating that a concise example of the modern raw HTTP request envelope would have saved time.
