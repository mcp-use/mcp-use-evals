The decisive wrong turn was placing the entry at repository root: the agent created `index.ts` (`[tool] fileChange({"event":"create","path":"index.ts"})`), while the grader only searched `src/server.ts` and `src/index.ts` (`entry: FAIL — no entry file found (tried: src/server.ts, src/index.ts)`). The SDK’s own local guidance likely encouraged this mismatch: `node_modules/mcp-use/README.md` said `Replace its index.ts`, and the CLI successfully reported `[mcp-use] built index.ts + views`, so the agent’s extensive runtime verification did not expose the grader-facing entry convention.

The agent leaned heavily on package-local resources rather than a skill file or fetched docs: it searched `node_modules/mcp-use` with `rg -n "registerTool|...|view|ui://|McpServer"` and read `node_modules/mcp-use/README.md`, `dist/tools.d.ts`, `dist/server.d.ts`, and `dist/react/types/register.d.ts`. Typed React integration was not immediately discoverable: the first typecheck failed with `Property 'incident' does not exist on type '{}'` and `Property 'incidents' does not exist on type '{}'`; only after inspecting the declaration comment `Augmented by the project's mcp-env.d.ts; empty by default.` did it create `mcp-env.d.ts`.

The npm scaffold also caused avoidable module-format friction. `npm init -y` generated `"type": "commonjs"`, and the first production start failed with `Failed to load the ES module` and `Cannot use import statement outside a module`. Inspection then showed contradictory duplicate fields, `"type": "module"` and later `"type": "commonjs"`, before the agent corrected `package.json` and successfully reached `mcp-use server running at http://localhost:3100/mcp`.

A final low-value detour was running `git diff` in a blank, non-Git workspace, producing `warning: Not a git repository.` Despite the entry-layout miss, the agent did perform protocol-level checks, with logs showing `tools/list`, `resources/list`, both `resources/read` calls, and both `tools/call` calls.
