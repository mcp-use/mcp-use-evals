The decisive wrong turn was placing the server at repository-root `index.ts`; the produced registration file confirms the same assumption with `mcp-env.d.ts: tools: typeof import("./index.js");`. Although the local CLI accepted it—`[mcp-use] built index.ts + views ... → .mcp-use/build/index.js`—the required harness searched `src/server.ts` or `src/index.ts`, so the otherwise implemented server was undiscoverable. The agent never checked or created either conventional `src/` entry path; its final file listing named only `Server/tools: [index.ts]`.

Discovery involved substantial package archaeology rather than a skill or fetched documentation page. The agent queried the npm README with `npm view mcp-use@2.0.4 readme --json`, then grepped installed internals using `rg -n "view:|views/|MCPServer|build --inline|resource" node_modules/mcp-use/dist node_modules/mcp-use/README.md` and inspected declarations such as `node_modules/mcp-use/dist/views/types.d.ts` and `node_modules/mcp-use/dist/react/hooks/use-tool-context.d.ts`. That investigation established API shape, but it did not expose the grader’s entry-file convention.
