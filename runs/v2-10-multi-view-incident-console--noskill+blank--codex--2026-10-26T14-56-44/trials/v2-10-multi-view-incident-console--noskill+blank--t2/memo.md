The decisive wrong turn was placing the entry at repository root: the SDK README explicitly instructed `Replace its index.ts`, and the agent created `index.ts`, while the produced configuration still had `"main": "index.js"` (`package.json`). Although the SDK accepted this—`[mcp-use] built index.ts + views ... → .mcp-use/build/index.js`—the grader only searched `src/server.ts` and `src/index.ts`, causing the entry failure. This is a scaffold/discovery mismatch the agent’s own build did not expose.

The agent leaned heavily on installed-package documentation and type declarations, first grepping `node_modules/mcp-use/README.md` and `node_modules/mcp-use/dist`, then inspecting `dist/tools.d.ts`, `dist/server.d.ts`, `dist/react/hooks/use-tool-context.d.ts`, and related files. The README’s root-level example—`Replace its index.ts with a view-bound tool like this`—likely reinforced the incompatible layout.

Startup initially failed because `npm init` created CommonJS configuration: `Warning: Failed to load the ES module` followed by `Cannot use import statement outside a module`. The agent inspected the build output and changed `package.json` to `"type": "module"`, after which the server reported `mcp-use server running at http://localhost:3100/mcp`. This module-mode requirement was not caught by `npx mcp-use build --inline`, which had already exited successfully.

Manual protocol verification also took two attempts. The first initialize request produced `the request headers and body disagree: an initialize request (legacy handshake) was sent with a modern MCP-Protocol-Version header`; retrying with body protocol `2025-11-25` succeeded.

A custom verification script then gave a misleading failure, `Error: list view marker missing`, because it searched compiled resource HTML for authored JSX. The agent corrected course after observing that `compiled HTML represents JSX attributes in its embedded module rather than as raw markup text`, and separately checked source markers such as `views/incident-list/view.tsx: <main data-view="incident-list"` while validating resource readability over MCP.
