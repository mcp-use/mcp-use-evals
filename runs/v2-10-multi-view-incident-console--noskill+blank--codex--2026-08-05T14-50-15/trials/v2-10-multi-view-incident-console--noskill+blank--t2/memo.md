The decisive wrong turn was placing the entry at repository root: the produced file is `index.ts`, while the deterministic check reports `entry: FAIL — no entry file found (tried: src/server.ts, src/index.ts)`. This is especially easy to miss because the installed CLI advertised broader discovery: its source listed `["src/index.ts", ... ,"index.ts", ...]`, and the local build confirmed `[mcp-use] built index.ts + views ...`. The agent therefore validated the SDK workflow but not the grader-compatible project layout.

The agent relied heavily on package-local discovery rather than a skill or fetched documentation: it searched `node_modules/mcp-use` with `rg -n "registerTool|registerApp|ui://|resource|McpServer|App"` and read `node_modules/mcp-use/README.md`, `dist/server.d.ts`, and React hook declarations. That exploration eventually exposed the generated typing mechanism through `/** Augmented by the project's mcp-env.d.ts; empty by default. */`.

The blank `npm init` scaffold created avoidable module friction because it emitted `"type": "commonjs"`. The first typecheck then failed with `TS1479: The current file is a CommonJS module ... referenced file is an ECMAScript module`, alongside unregistered view typing errors such as `Property 'incident' does not exist on type '{}'`. Running `npx mcp-use typecheck` resolved the latter by reporting `[mcp-use] created mcp-env.d.ts`, suggesting the generated declaration requirement was not obvious before inspecting package internals.

Verification also lost time to test-script mistakes rather than server behavior. The first parser failed with `TypeError: Cannot read properties of undefined (reading 'slice')`; two subsequent checks incorrectly reported `"markers": { "list": false, "detail": false }`. Inspection later showed the escaped marker in the built output—`.mcp-use/build/manifest.json:13:data-view=\\\"incident-list\\\"`—and the corrected check finally returned `"list": true, "detail": true`. The agent also treated expected process termination as failed tool output: the server shutdown returned `exitCode:130`, and the final combined server process returned `exitCode:143`.
