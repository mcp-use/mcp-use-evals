The repair itself was localized, but SDK discovery cost several calls. The agent first searched before dependencies existed and hit `rg: node_modules/mcp-use: IO error ... No such file or directory`, then ran `npm install`. It subsequently leaned heavily on installed package internals, searching `node_modules/mcp-use/dist/server.d.ts`, `dist/index.js`, and the package README for `MCPServer` and `listen`; one lookup still failed with `exitCode":1,"output":""`. The declaration’s example, `await server.listen(3000);`, did not directly document the desired environment-driven no-argument behavior, while the final source relied on `// With no explicit argument, mcp-use reads PORT and defaults to 3000.`

Most avoidable time came from a hand-written SSE verification parser. The first full test mutated inventory successfully—`"text":"Reserved 3 of coffee-mug"`—but the script nevertheless threw `Error: reserve_stock failed: 200` because it searched using `body.split("\\n")`. The agent acknowledged that “`my response parser treated the stream delimiter literally`,” then had to find three wrapper processes via `pgrep -af 'tsx src/server.ts|node.*server.ts'`, kill them, restart the server to reset in-memory state, and rerun with `body.match(/^data: (.*)$/m)`.

The process-management output was also mildly confusing: intentional server termination surfaced as `exitCode":143` and `"status":"failed"` even after successful HTTP calls, including logs such as `tools/call reserve_stock` and `tools/list`. Despite these papercuts, the source changes remained narrowly scoped: `src/server.ts` replaces throws with `return result(\`SKU ${sku} not found\`)`, changes reservation to `inventory.set(sku, available - quantity)`, and makes restock update shared state with `inventory.set(sku, available + quantity)`.
