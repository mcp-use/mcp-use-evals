The main time cost was API discovery: the agent first queried npm metadata and the package README with `npm view mcp-use version description repository.url dist.tarball` and `npm view mcp-use readme`, then searched installed SDK files using `rg -n "listen\(|Streamable|HTTP|serve\(" node_modules/mcp-use/dist`. It ultimately relied on declaration files, inspecting `node_modules/mcp-use/dist/server.d.ts` and `node_modules/mcp-use/dist/tools.d.ts`, to determine the `MCPServer.listen` and typed tool APIs.

Dependency setup had a small warning around executable installation: npm reported `esbuild@0.28.2 (postinstall: node install.js)` was “`not yet covered by allowScripts`,” though subsequent `npx tsc --noEmit` and `npx tsx src/server.ts` worked.

The only clear wrong turn came during final verification: the agent combined a successful invalid-input request with `git status --short && git diff`, but the blank workspace was not a repository, producing `fatal: not a git repository` and making the command return `exitCode:128`. The running-server command later appeared as `exitCode:130`, despite its log confirming `MCP server listening at http://localhost:3100/mcp` and successful `tools/list` and `tools/call` requests. This did not affect the implementation, but made an otherwise successful verification sequence look failed at the tool-call level.
