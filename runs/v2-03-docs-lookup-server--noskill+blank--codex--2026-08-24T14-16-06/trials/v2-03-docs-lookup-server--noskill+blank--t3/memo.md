The agent relied heavily on package discovery and installed declarations rather than a skill file: it fetched the npm README with `npm view mcp-use readme`, then searched SDK internals using `rg -n "resource\\(|resources|Streamable|serve\\(" node_modules/mcp-use/dist`. The declarations provided useful API shape, including `resource(definition: ResourceDefinition, callback: ResourceCallback...)` and `listen(port?: number | undefined, options?: ListenOptions)`.

Dependency-version alignment caused avoidable churn. The agent first installed `zod@3`, then switched with `npm install zod@4`. It also assumed matching server/client versions, but `npm install -D @mcp-use/client@2.3.1` failed with `No matching version found for @mcp-use/client@2.3.1`; only after querying `npm view @mcp-use/client version dist-tags --json` did it install `@mcp-use/client@2.1.5`. This exposes a versioning papercut because the server was `mcp-use@2.3.1` while the available client was `"version": "2.1.5"`.
