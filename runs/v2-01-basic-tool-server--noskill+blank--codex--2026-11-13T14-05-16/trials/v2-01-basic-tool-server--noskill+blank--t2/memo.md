The main cost was API discovery: the agent queried npm (`npm view mcp-use readme --json`), fetched the repository README (`curl -fsSL https://raw.githubusercontent.com/mcp-use/mcp-use/main/README.md`), then fetched an unrelated onboarding prompt (`curl -fsSL https://mcp-use.com/prompt.md`) whose content began `I'm new to Manufact. Help me connect it to this AI client`. It ultimately cloned and searched the repository (`git clone --depth 1 https://github.com/mcp-use/mcp-use.git`) rather than using a skill file; the first search assumed the wrong monorepo layout and produced `rg: /tmp/mcp-use-repo/packages: No such file or directory`.

The useful API shape came from grepping the cloned SDK source and examples, especially the `MCPServer` documentation containing `await server.listen(3000);` and the Zod example at `/tmp/mcp-use-repo/examples/typescript/schema-validators/zod/src/index.ts`. Once found, implementation was direct: `src/server.ts` uses `inputSchema: addInput` and `await server.listen(port, { host: "0.0.0.0" });`.

A runtime papercut was the SDK warning `[mcp-use] listen() is serving on 0.0.0.0 without Host validation`, triggered by the explicit public bind in `src/server.ts:36`. Both background server tool calls were consequently displayed as failed after manual interruption—`"exitCode":1` with `^C`—despite successful requests such as `tools/call add /mcp 200`. The agent also repeated server startup and invocation after already receiving `"text":"41.75"`, adding an unnecessary second verification cycle.
