Discovery required package inspection rather than a straightforward npm README: `npm view mcp-use readme` returned `""`, after which the agent searched `node_modules/mcp-use` with `rg -n "Streamable|streamable|HTTP|McpServer|tool\("` and consulted `node_modules/mcp-use/README.md`, `dist/server.d.ts`, `dist/tools.d.ts`, and `dist/config.d.ts`. The initial scaffold configuration fought the implementation. `npm init -y` created `"type": "commonjs"`, and the first check failed with `Cannot find name 'process'` and `The current file is a CommonJS module and cannot use 'await' at the top level.` This required modifying both `package.json` and `tsconfig.json`, even though `@types/node` had already been installed.

Process management cost extra time. The agent then had to inspect processes via `ps -ef | rg 'tsx|index\.ts|node'` and later kill several wrapper/child PIDs with `kill 511 522 602 645 656`.

Manual protocol verification also took a wrong turn. Sending header/body version `2026-07-28` produced `an initialize request (legacy handshake) was sent with a modern MCP-Protocol-Version header`, while later requests failed because they were `missing the required per-request envelope key(s): _meta`. Retrying without that modern header and with body version `"2025-03-26"` succeeded, showing a discoverability gap around the SDK’s supported handshake/envelope conventions.
