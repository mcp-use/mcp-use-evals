The decisive wrong turn was entry placement: the SDK README explicitly said `Replace its index.ts`, but the agent created root-level `server.ts` (`[tool] fileChange({"event":"create","path":"server.ts"})`). Although the CLI accepted it—`built server.ts + views ... → .mcp-use/build/index.js`—the grader only searched `src/server.ts` and `src/index.ts`, so the otherwise implemented server was undiscoverable.

The agent relied heavily on package internals rather than a skill or fetched docs: it ran `npm view mcp-use@2.0.4 readme`, repeatedly grepped `node_modules` for `"ui://|MCPServer|\\.tool\\("`, and inspected `node_modules/mcp-use/README.md`, `dist/tools.d.ts`, `dist/server.d.ts`, CLI build code, and React hook declarations. That investigation surfaced useful conventions such as `Create views/weather-card/view.tsx`, but did not prevent the entry-path mismatch.

Dependency compatibility caused a concrete detour. The first typecheck failed because the installed project Zod was `zod@4.0.17` while SDK dependencies used `zod@4.5.4`, producing `Property 'jsonSchema' is missing`; the agent diagnosed this via `npm list zod`, then changed `package.json` and reinstalled.

Generated React typing also created friction. After rebuilding, both views failed with `'context.toolOutput' is of type 'unknown'`, despite generated `mcp-env.d.ts` declaring `tools: typeof import("./server.js")`. The produced views ultimately used casts such as `(context.toolOutput as IncidentDetailOutput).incident`, sacrificing the promised inferred typing to make typecheck pass.

Verification consumed extra time through shell-script mistakes. One Node verifier failed with `Cannot read properties of undefined (reading 'slice')` after splitting on the literal escaped newline (`body.split("\\n")` in the echoed script), and the final marker check unexpectedly ended with `fatal: not a git repository`. The earlier successful verifier also reported `"containsExpectedMarker": false` for both resources even though source contains `<main data-view="incident-list"` and `<main data-view="incident-detail"`, yet the agent concluded `Verified successfully` without resolving that discrepancy.
