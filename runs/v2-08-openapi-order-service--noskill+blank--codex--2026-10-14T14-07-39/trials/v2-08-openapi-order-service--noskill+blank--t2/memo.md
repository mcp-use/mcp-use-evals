The main discovery cost was API-shape investigation in installed packages: the agent ran `rg -n "fromOpenAPI|Streamable|streamable" node_modules/mcp-use` and inspected `node_modules/mcp-use/dist/server.d.ts`, `openapi/types.d.ts`, and the MCP client declarations before concluding that JSON bodies become a nested `body` argument: `The SDK’s OpenAPI helper generates a single \`body\` argument`. This suggests the generated tool-input convention was not obvious without grepping `node_modules`; no skill file or external docs URL was used in the visible transcript.

A notable SDK papercut was default telemetry, discovered only after the first successful lifecycle run. The SDK created `.mcp-use/usage.json`, and inspection found `if(env("MCP_USE_ANONYMIZED_TELEMETRY")==="false")return!0`; the agent then said, `I found the SDK enables anonymized telemetry by default, which would violate the no-network requirement.` It deleted the generated file and added `process.env.MCP_USE_ANONYMIZED_TELEMETRY = "false";` in `src/server.ts`, then reran verification. This late discovery added several searches and another full test cycle.

Two verification commands produced avoidable false alarms. Running the long-lived entry point yielded `exitCode":130` despite printing `Order MCP server listening at http://localhost:3123/mcp`, so the harness labeled a healthy server start as `"status":"failed"`. A repository hygiene check also failed because the blank workspace was not a Git checkout: `fatal: not a git repository (or any of the parent directories): .git`; the agent then repeated the remaining `rg` and `ls` checks without Git.

The final implementation itself required no compile/debug iteration: the first combined check reported `exitCode":0` for `npm install && npx tsc --noEmit`, and the first lifecycle execution ended with `Verified create, retrieve with events, cancel, and not found lifecycle.`
