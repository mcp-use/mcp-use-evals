The decisive wrong turn was placing the server at repository-root `index.ts` rather than a grader-recognized entry path: the produced source is `index.ts`, while the deterministic result says `no entry file found (tried: src/server.ts, src/index.ts)`. This is especially notable because the agent relied on package documentation that stated `index.ts — Server entry file for tool definition and metadata`, and the SDK itself accepted that layout with `[mcp-use] built index.ts + views ... → .mcp-use/build/index.js`. The SDK/CLI convention therefore appeared valid locally but did not align with the expected project entry convention.

Discovery involved substantial package archaeology. The npm README attempt failed with `SyntaxError: /tmp/mcp-use-readme.json: Unexpected end of JSON input`, after which the agent inspected `node_modules/mcp-use/README.md`, several `dist/*.d.ts` files, and grepped installed CLI internals with `rg -n "interface Register.*tools|mcp-env.d.ts..." node_modules`. No skill file or fetched docs URL appears; the main resources were the packaged README, declarations, and node_modules implementation.

Typed view output was initially surprising: `context.toolOutput` remained `unknown`, producing errors such as `views/incident-list/view.tsx(14,62): error TS18046`. The agent had to inspect `node_modules/mcp-use/dist/react/types/register.d.ts` and manually create `mcp-env.d.ts` with `tools: typeof import("./index.js")` before typechecking passed. This generated-registration requirement was not discovered until after implementation.

Manual protocol verification also took several retries. The first handshake failed because `the request headers and body disagree`, and the second failed with `Client must accept both application/json and text/event-stream`; adding the required `Accept` header finally returned `HTTP/1.1 200 OK`. A first resource assertion then failed with `Error: list resource read failed`, although inspection showed `text/html;profile=mcp-app 884967 true`; the agent rewrote the verification script and subsequently reported `Verified: 2 tools, 2 readable MCP App HTML resources`.

The final cleanup also generated avoidable noise by assuming Git metadata: `fatal: not a git repository`.
