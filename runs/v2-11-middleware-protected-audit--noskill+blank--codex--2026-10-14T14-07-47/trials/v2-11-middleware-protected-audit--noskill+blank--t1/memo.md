The main miss was response wording: `src/server.ts` returns ``text: `record:${id}``` and ``text: `deleted:${id}```, while the deterministic checks expected strings containing `Record R-1` and `deleted R-1`. The agent’s live verification reinforced the wrong contract because it accepted `record:record-1` and `deleted:record-1`, then concluded, “`The live checks passed`,” without asserting expected response text.

Discovery took several steps. Fetching the npm README failed with `SyntaxError: /tmp/mcp-use-readme.json: Unexpected end of JSON input`; the agent then relied on the installed `node_modules/mcp-use/README.md` and declaration files including `node_modules/mcp-use/dist/server.d.ts` and `node_modules/mcp-use/dist/middleware/mcp-middleware.d.ts`. The declaration inspection did expose the exact middleware example: `server.use("mcp:tools/call", async (ctx, next) => { ... return next(); });`.

Setup also had avoidable dependency/config churn. The agent initially installed `zod@^3.24.0`, then ran `npm install zod@^4.4.3`; the final manifest showed `"zod": "^4.6.7"`. Its first typecheck failed with `Cannot find name 'process'` and `The current file is a CommonJS module and cannot use 'await' at the top level`, requiring package and tsconfig edits. A combined verification command also assumed Git metadata and failed with `warning: Not a git repository`.

The protocol-level behavior itself was verified directly: the denied response contained `"approval required"`, and the resource returned `"1|read_record|allowed\n2|delete_record|denied\n3|delete_record|allowed"`. However, the final statement “`The live checks passed`” was overconfident because those checks validated ordering and authorization but not the externally expected read/delete text.
