The main friction was SDK discovery. The agent first tried the npm metadata/readme route with `npm view mcp-use readme`, but the result was empty: `0 /tmp/mcp-use-readme.json`. It then downloaded and inspected the package itself via `npm pack mcp-use` and extracted `package/README.md`, `package/dist/server.d.ts`, and `package/dist/tools.d.ts`; the declaration inspection supplied the needed API shape, including `listen(port?: number | undefined, options?: ListenOptions)` and its returned `url`.

Protocol verification hit a CLI dependency surprise. Running `npx mcp-use client connect` said `[mcp-use] installing @mcp-use/client…` and `added 1 package`, but immediately failed with `@mcp-use/client is not installed` and instructed `npm install @mcp-use/client`. The agent had to explicitly run `npm install --save-dev @mcp-use/client` before the same lifecycle command succeeded. This is a concrete papercut because the CLI’s apparent auto-install did not make the command usable.

The final verification chain also reported failure for an irrelevant environmental check: after successful calls showing `Claimed ticket 2.` twice and `Open tickets (1): VPN access request`, `git status --short` produced `fatal: not a git repository (or any of the parent directories): .git`, making the combined command exit with code 128 despite the substantive checks succeeding.
