The decisive wrong turn was placing the entry point at repository root: the transcript records `fileChange({"event":"create","path":"index.ts"})`, while the grader searched `src/server.ts, src/index.ts`; the produced server is therefore only at `index.ts`, despite correctly containing `export default server;`. This was masked because the SDK CLI accepted that layout and reported `[mcp-use] built index.ts + views (incident-detail, incident-list)`, then successfully started with `mcp-use server running at http://localhost:3123/mcp`. The agent’s final statement, ``npx mcp-use build --inline` succeeds`, consequently did not catch compatibility with the required entry convention.

API discovery consumed several probes into installed package internals, including `sed -n '1,260p' node_modules/mcp-use/dist/server.d.ts`, inspection of `node_modules/mcp-use/dist/views/index.d.ts`, and grepping CLI internals with `rg -n "entry|index\\.ts|view\\.tsx|mcp-env" ...`. That investigation did find the view convention—the grep output explicitly contains `P(r,i.name,"view.tsx")`—but it did not lead the agent to a grader-compatible `src/index.ts`.

The React hook typing was another papercut. The first typecheck produced repeated errors such as `Property 'id' does not exist on type '{}'` and `Property 'incidents' does not exist on type '{}'`. The eventual workaround uses assertions rather than inferred tool output types: `views/incident-detail/view.tsx` has `(toolOutput as Incident | undefined)`, and `views/incident-list/view.tsx` has `(toolOutput as { incidents: Incident[] } | undefined)?.incidents`.

Verification also had avoidable noise: the combined resource/tool curl emitted a very large inline HTML response beginning `"text":"<!doctype html>...`, while the server process ended with `exitCode":130` after successful calls. The final housekeeping command failed because it unconditionally ran Git status in a blank directory: `fatal: not a git repository`.
