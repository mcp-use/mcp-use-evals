The main discovery detour was probing the SDK before dependencies existed: `find node_modules/mcp-use` failed with `No such file or directory`, after which the agent had to run `npm install`. Once installed, it leaned heavily on package internals rather than a skill file or external docs, grepping `node_modules/mcp-use` for `listen`, `streamable`, and `http`, then reading `node_modules/mcp-use/dist/server.d.ts`, `config.d.ts`, `listen-address.d.ts`, and the packaged README. This was useful for resolving listener behavior, reflected in: `The SDK’s listen() resolves PORT itself (with its documented 3000 fallback)`.

A verification command unnecessarily assumed a Git checkout: `npx tsc --noEmit && git diff --check && git diff -- src/server.ts package.json`. It exited 129 with `warning: Not a git repository`, forcing another final typecheck even though the compile step had already completed. This is scaffold friction rather than an SDK problem.

The agent manually exercised raw streamable-HTTP JSON-RPC with several verbose `curl` calls. Its initialize request proposed `"protocolVersion":"2026-07-28"`, while the server negotiated `"protocolVersion":"2025-11-25"`; subsequent calls therefore needed the explicit header `Mcp-Protocol-Version: 2025-11-25`. The checks worked, but this shows protocol-level verification required non-obvious headers and SSE parsing (`content-type: text/event-stream`, followed by `event: message`).

The actual repair was direct and small in `src/server.ts`: unknown-SKU throws became `return result(\`SKU ${sku} not found\`)`, insufficient stock became `return result(\`insufficient stock for ${sku}\`)`, reservation changed to `inventory.set(sku, available - quantity)`, and restock added `inventory.set(sku, available + quantity)`.
