The bundled README’s quickstart was directly useful, showing `import { MCPServer } from "mcp-use"`, `inputSchema: weatherInput`, and `export default server;`; the declaration search supplied the less-visible `listen` and port API through `rg -n "listen\\(" node_modules/mcp-use/dist/server.d.ts`.

Dependency installation produced a potentially confusing environment warning twice: `esbuild@0.28.2 (postinstall: node install.js)` was “`not yet covered by allowScripts`,” with npm suggesting `npm install-scripts approve <pkg>`, although `npx tsc --noEmit` and runtime verification still succeeded. The verification process also reported both intentionally stopped server processes as failures—`{"exitCode":130,...,"status":"failed"}`—despite their logs showing successful requests such as `tools/call add /mcp 200`; this is noisy and could mislead an agent into investigating a healthy server.

The agent restarted the server solely for a final listing check: after already receiving `tools/call add /mcp 200`, it said, “`I’ll do one final protocol check to confirm that only the typed add tool is advertised`,” then launched `PORT=3100 npx tsx src/server.ts` again.
