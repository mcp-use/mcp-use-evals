The decisive mistake was placing the server at repository-root `index.ts` rather than a conventional `src` entry; the final file listing shows `./index.ts` and no `src/server.ts` or `src/index.ts`: `find ...` → `./index.ts ... ./views/incident-list/view.tsx`. The agent explicitly saw that the CLI supports an override—`--entry <path> Server entry module`—but neither moved the file nor configured that option, so its successful local build of `index.ts` did not match the grader’s entry discovery.

Discovery relied heavily on installed-package inspection rather than a skill file or fetched docs: it ran `rg -n "registerTool|registerApp|create.*Server|ui://|resource|mcp-use build|McpServer" node_modules/mcp-use node_modules/@mcp-use` and read `node_modules/mcp-use/README.md` plus several `dist/*.d.ts` files. The first typecheck failed because generated React tool typings were absent: `Property 'id' does not exist on type '{}'` and `Property 'incidents' does not exist on type '{}'`. Running `npx mcp-use typecheck` resolved this by generating `[mcp-use] created mcp-env.d.ts`; this generation prerequisite is a usability papercut because plain `npx tsc --noEmit` initially failed.

Verification also lost time to a brittle search for source-form JSX in bundled HTML: `Error: list marker`. Inspection then showed the bundle encoded the attribute as `\"data-view\":\`incident-list\``, after which the revised assertion passed with `MCP verification passed`.
