The decisive wrong turn was placing the entry point at repository root: `index.ts` contains `export default server;`, while the deterministic check reports `no entry file found (tried: src/server.ts, src/index.ts)`. This was encouraged by the SDK’s own README, which told the agent, `Replace its index.ts with a view-bound tool like this`, and the SDK build accepted that layout with `[mcp-use] built index.ts + views ... → .mcp-use/build/index.js`. The mismatch between SDK documentation/build discovery and the grader’s expected `src/` convention caused every runtime contract check to be blocked despite the agent’s successful local verification.

Dependency installation also lost time because the first attempt used Zod 3 and failed with `peer zod@"^4.2.0" from @mcp-use/client@2.4.6`; the agent retried using `zod@'^4.2.0'`. The resulting install reported `11 high severity vulnerabilities`, another ecosystem papercut even though installation completed.

With no skill file used, the agent leaned heavily on installed-package documentation and declarations, first running `rg ... node_modules/mcp-use/README.md node_modules/mcp-use/dist`, then inspecting `node_modules/mcp-use/dist/server.d.ts` and `node_modules/mcp-use/dist/react/hooks/use-tool-context.d.ts`. That discovery work did identify the view directory convention from the README: `Create views/weather-card/view.tsx. The directory name matches view.name on the tool`.

The first typecheck/build attempt failed because the incident data’s readonly inference did not match the mutable output schema: `structuredContent: { incidents: readonly [...] }` was `not assignable to parameter of type 'ToolCallback...'`. The agent modified `index.ts` and subsequently got both `npx tsc --noEmit` and the inline build to pass.

The resource-marker verification initially produced misleading negatives—`hasMarker: false` for both resources—because the built HTML encoded the JSX marker differently. The agent then searched the decoded resource/bundle and found `data-view\":\`incident-list\`` and `data-view\":\`incident-detail\``, showing extra verification friction around generated inline resources.
