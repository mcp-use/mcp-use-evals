The main discovery friction was determining the SDK’s server and transport API. The agent first queried npm with `npm view mcp-use version description repository.url dist.tarball` and fetched the package README, which pointed to `https://docs.mcp-use.com/v2/typescript/getting-started/welcome`; it then relied more heavily on installed declarations via `rg -n "class MCPServer|listen\\(|streamable|http" node_modules/mcp-use` and `sed -n '1,430p' node_modules/mcp-use/dist/server.d.ts`. It also had to inspect protocol details manually with `rg -n "MCP-Protocol-Version|protocolVersion.*202|initialize" node_modules/mcp-use/dist` before constructing raw curl JSON-RPC requests using `MCP-Protocol-Version: 2025-11-25`.

A notable SDK papercut was automatic telemetry identity persistence: after verification, `find .mcp-use -maxdepth 3 -type f` revealed `.mcp-use/usage.json`. The agent then grepped bundled internals for the opt-out—`rg -n "isUsageDisabled|DISABLE_USAGE|MCP_USE.*USAGE" node_modules/mcp-use/dist`—deleted the generated file, and added `process.env.MCP_USE_ANONYMIZED_TELEMETRY ??= "false";` at `src/server.ts:3`. This was unrelated cleanup that consumed several tool calls and required reading minified SDK output.

Verification was more cumbersome than necessary because the agent manually implemented streamable-HTTP calls with curl and SSE stripping—`| sed -n 's/^data: //p'`—rather than using a client or inspector. It also performed an unnecessary repository check in a blank directory: `git status --short` failed with `fatal: not a git repository`. The long-running server commands repeatedly ended with `exitCode":130`, including after successful request logs such as `tools/call close_ticket`; while expected when stopping a server, the tooling surfaced these normal shutdowns as `"status":"failed"`, adding noise to an otherwise successful run.
