The decisive miss was the read tool’s response casing: `src/server.ts` returns ``text: `record ${id}```, while the deterministic check expected text containing `Record R-1`. The agent’s own verification used lowercase input and accepted lowercase output—`"id":"r-1"` produced `"text":"record r-1"`—so it never exercised the grader’s exact `R-1` case or checked the expected capitalization.

SDK discovery required inspecting installed declarations: the agent ran `rg -n "mcp:tools/call|streamable|create.*Server|registerTool|resource" node_modules/mcp-use` and then opened `node_modules/mcp-use/dist/server.d.ts`, `middleware/mcp-middleware.d.ts`, `tools.d.ts`, and `config.d.ts`. Its first documentation attempt failed because `npm view mcp-use@2.0.4 readme --json` yielded an empty/truncated file and `SyntaxError: /tmp/mcp-use-readme.json: Unexpected end of JSON input`.

Process handling also cost time. After starting with `PORT=3100 npx tsx src/server.ts`, a second start failed with `Error: listen EADDRINUSE: address already in use 127.0.0.1:3100`; the agent later found three related processes—`npm exec tsx src/server.ts`, `node node_modules/.bin/tsx src/server.ts`, and the loader process—and explicitly killed them with `kill 411 424 435`.

A blank-directory papercut appeared when the final validation chained Git commands despite no repository: `fatal: not a git repository (or any of the parent directories): .git`. The SDK also created `.mcp-use/usage.json` during execution, which the agent subsequently deleted via `fileChange({"event":"delete","path":".mcp-use/usage.json"})`.
