The main miss was the decline error wording: `src/server.ts` returns `text: "Deployment was not approved."`, while the deterministic check required a result containing `decline`. The local test did not assert the error text; `tests/deployment-flow.test.ts` only checks `assert.equal(declined.isError, true)` and absence of `"resultType"`/`"inputRequests"`. This allowed the agent to conclude `Accepted approval and terminal decline verified.` without catching the contract mismatch.

The agent relied heavily on grepping installed package internals rather than a skill file or fetched docs, using `rg -n "inputRequired|inputResponse|acceptedContent|Streamable|streamable|HTTP|McpServer" node_modules/mcp-use` and inspecting `node_modules/mcp-use/dist/server.d.ts` plus `@modelcontextprotocol/server` implementation files. That discovery did establish the raw helper API, but consumed several calls.

HTTP verification took a wrong turn because the initialization request asked for `"protocolVersion":"2026-07-28"` but the server negotiated `"protocolVersion":"2025-11-25"`. The subsequent tool call failed with `Cannot request input 'deployment-approval' ... the client on this 2025-era connection did not declare the required capability`. After this, verification shifted to directly calling the exported `requestDeployment` helper rather than completing the multi-round HTTP flow.

There was avoidable TypeScript/config churn. The first typecheck failed with `Cannot find name 'process'`, requiring Node types in `tsconfig.json`. Later changes introduced `The 'import.meta' meta-property is not allowed in files which will build into CommonJS output`, followed by several test-narrowing errors such as `Property 'resultType' does not exist` and `Object is possibly 'undefined'`. A final combined validation also failed for an unrelated repository assumption: `warning: Not a git repository` from `git diff --check`.

The final source otherwise encoded terminal retry handling explicitly at `src/server.ts`: `if (inputResponses !== undefined)` and the fallback `{ isError: true as const, ... }`, but the tests focused on shape rather than externally observable message semantics.
