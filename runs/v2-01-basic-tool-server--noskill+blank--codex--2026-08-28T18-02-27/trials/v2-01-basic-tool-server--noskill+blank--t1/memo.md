The agent spent substantial discovery effort before implementation, first querying npm with `npm view mcp-use version description dist-tags --json`, then inspecting the package via `npm pack mcp-use@2.3.3 --dry-run --json`, fetching the README from `https://unpkg.com/mcp-use@2.3.3/README.md`, and fetching the unrelated deployment-oriented prompt at `https://mcp-use.com/prompt.md`. That prompt emphasized scaffolding and deployment—`npx -y create-mcp-use-app@latest my-mcp-app --template mcp-apps` and `npx -y mcp-use@latest deploy`—despite the task requiring work directly in a blank directory.

The most useful API discovery came only after installation, through grepping declarations in `node_modules`: `sed -n '1,280p' node_modules/mcp-use/dist/server.d.ts` and `rg -n "listen\\(|streamable|HTTP|start\\(" node_modules/mcp-use/README.md node_modules/mcp-use/dist`. The declaration supplied the critical transport behavior directly: `Serve over HTTP on Node` and `listen(port?: number | undefined...): Promise<{ ... url: string; }>`. No mcp-use skill file was used; the fetched prompt merely instructed `Install the mcp-use skill`, but the transcript contains no corresponding installation command.

Verification hit a protocol-version papercut on the first handshake: the request used `MCP-Protocol-Version: 2026-07-28`, and the SDK returned `400 Bad Request` with `an initialize request (legacy handshake) was sent with a modern MCP-Protocol-Version header`. Retrying with `MCP-Protocol-Version: 2025-06-18` immediately produced `HTTP/1.1 200 OK`, so the error was actionable but required protocol-version knowledge not surfaced during initial implementation.
