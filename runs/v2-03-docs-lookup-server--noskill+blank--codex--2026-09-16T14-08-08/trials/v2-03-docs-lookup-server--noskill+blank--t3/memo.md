The main discovery cost was learning the SDK API from installed declarations rather than readily surfaced package guidance: the agent first ran `npm view mcp-use readme --json`, which returned no README content, then searched `node_modules/mcp-use` for `"class MCPServer|streamable|resource\\("` and inspected `node_modules/mcp-use/dist/server.d.ts`, `resources.d.ts`, and `tools.d.ts`. This worked, but required several exploratory commands before implementation.

A notable SDK papercut was telemetry enabled by default. After verification created `.mcp-use/usage.json`, the agent inspected bundled code and found `if(env("MCP_USE_ANONYMIZED_TELEMETRY")==="false")return!0`; it then changed `src/server.ts` to set `process.env.MCP_USE_ANONYMIZED_TELEMETRY ??= "false";` before dynamically importing `"mcp-use"`, and deleted `.mcp-use/usage.json`. The agent explicitly described the concern as `"the SDK enables anonymous telemetry by default, which can persist an identifier and send a request."` This caused a second typecheck and full runtime-verification cycle.

There was also a small environment-assumption detour: the final hygiene command used `git diff --check && git status --short`, but failed with `"warning: Not a git repository."` Because it was chained with `&&`, the intended source grep did not run until a separate command.

The implementation and protocol verification were otherwise direct. The agent manually exercised `/mcp` using repeated `curl` JSON-RPC requests and confirmed outputs including `"deployment: Deployment"` and `"No documentation pages matched your query."` Both server runs ended with exit code 130 only because the long-running process was stopped; their logs showed successful requests such as `"resources/read docs://authentication /mcp 200"` and `"tools/call search_docs /mcp 200"`.
