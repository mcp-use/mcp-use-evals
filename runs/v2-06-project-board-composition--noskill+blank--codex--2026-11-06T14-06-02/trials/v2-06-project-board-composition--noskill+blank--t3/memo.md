The main discovery cost was learning the SDK API from package artifacts rather than an immediately usable example: the agent fetched the npm README, which pointed to `https://docs.mcp-use.com/v2/typescript/getting-started/welcome`, then searched installed declarations with `rg -n "resource\\(|resources|Streamable|streamable|listen|serve" node_modules/mcp-use/dist` and inspected `node_modules/mcp-use/dist/server.d.ts` plus `resources.d.ts`.

The first implementation did not typecheck because the generated npm scaffold remained CommonJS and the TypeScript config omitted Node types: `Cannot find name 'process'` and `The current file is a CommonJS module and cannot use 'await' at the top level.` The agent had already installed `@types/node`, so this was configuration friction rather than a missing dependency; it then modified both `package.json` and `tsconfig.json`.

A notable SDK papercut was telemetry creating a file despite the requirement’s file-free state intent: verification found `./.mcp-use/usage.json`, after which the agent deleted it and changed the source. The final workaround is explicit in `src/server.ts`: `process.env.MCP_USE_ANONYMIZED_TELEMETRY ??= "false";`. This required stopping, cleaning, restarting, and rerunning the lifecycle.

Server startup also emitted a security warning that required interpretation rather than action for this task: `[mcp-use] listen() is serving on 0.0.0.0 without Host validation... set allowedHosts to restrict it.` Process management produced noisy nonzero-looking results during otherwise successful verification, including `exitCode":143` after terminating the server and `fatal: not a git repository` from an unnecessary `git status --short`.

The agent verified the lifecycle twice; the first complete run already showed `Open issues: 0`, `Created issue 1`, `assigned to Ada`, `status: resolved`, and both `Issue 999 not found` responses, but it restarted and repeated those checks after adding the telemetry workaround.
