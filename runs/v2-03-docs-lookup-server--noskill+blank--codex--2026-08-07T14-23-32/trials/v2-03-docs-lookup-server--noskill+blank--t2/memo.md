The main friction was SDK/API discovery: the agent inspected package internals with `find node_modules/mcp-use`, `sed ... node_modules/mcp-use/dist/resources.d.ts`, and `rg -n "listen\\(" node_modules/mcp-use/dist/server.d.ts` before implementing, rather than relying on a skill file or external docs.

Verification took two wrong turns around the streamable HTTP handshake. The first request mixed a modern header with a legacy initialize body and received `Bad Request: the request headers and body disagree`. After changing the protocol version, the next request still failed because `Client must accept both application/json and text/event-stream`. Adding `Accept: application/json, text/event-stream` then produced a successful initialize response containing `"protocolVersion":"2025-06-18"`. These errors are descriptive, but the requirement to align handshake style and advertise both response media types was a protocol papercut that cost two extra attempts.

The implementation itself was direct once the declarations were inspected: `src/server.ts` uses `server.resource(...)`, `server.resourceTemplate(...)`, a Zod `inputSchema: searchDocsInput`, and `server.listen(listenPort)`. The requested checks then succeeded, including the unknown-page response `"Documentation page not found."`, the unique search result `{"slug":"deployment","title":"Deployment"}`, and the empty result `{"results":[]}`.
