The decisive miss was project layout: the server was created at root as `index.ts`, while the grader only searched `src/server.ts` and `src/index.ts` (`entry: FAIL — no entry file found (tried: src/server.ts, src/index.ts)`). The agent’s own final inventory showed only `./index.ts`, yet it concluded “`Verified 2 tools, 2 HTML MCP App resources, and independent result view bindings.`”; testing through the SDK CLI therefore did not catch the grader-facing entry convention.

Discovery relied heavily on package inspection rather than a skill file: it queried `npm view mcp-use@2.0.4`, then searched installed declarations with `rg -n "registerTool|registerApp|ui://|view" node_modules/mcp-use` and opened files such as `node_modules/mcp-use/dist/server.d.ts`. The npm README attempt failed with `SyntaxError: /tmp/mcp-use-readme.json: Unexpected end of JSON input`, adding an early detour.

Dependency resolution also cost a retry: the first install failed because `@mcp-use/client@2.4.5` required `peer zod@"^4.2.0"` while the project had `zod@3.25.76`; the agent then modified `package.json` and reinstalled.

Typed view output was initially surprising: `useToolContext` inferred `{}`, producing errors such as `Property 'id' does not exist on type '{}'` and `Property 'incidents' does not exist on type '{}'`. The agent ran `npx mcp-use typecheck`, inspected `mcp-env.d.ts`, temporarily edited both views, and only near the end recognized that “`the generated MCP view type registration needs to be included in the TypeScript project`,” then updated `tsconfig.json`.

Verification had two avoidable dead ends. Searching serialized resource HTML for JSX markers reported `"hasMarker":false`, and a later assertion failed with `Error: list marker missing`; the marker exists in rendered React source at `views/incident-list/view.tsx` (`<main data-view="incident-list"`) and `views/incident-detail/view.tsx` (`<main data-view="incident-detail"`), not necessarily as literal HTML in the bundled resource. The fallback renderer check then failed because `Chrome, Chromium, Edge, or Brave was not found. Set MCP_USE_CHROME_PATH.` Despite these detours, direct MCP calls eventually showed both resource MIME types and independent result view URIs.
