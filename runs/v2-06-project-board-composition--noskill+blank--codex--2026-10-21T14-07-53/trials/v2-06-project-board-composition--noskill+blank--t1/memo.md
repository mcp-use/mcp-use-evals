The main SDK papercut was Zod version compatibility. The agent initially installed `zod@4.1.12`, while `mcp-use@2.11.0` resolved SDK packages using `zod@4.6.7`, as shown by `npm ls zod`. TypeScript then reported that the schema lacked `jsonSchema`: `Property 'jsonSchema' is missing`, and callback inputs degraded to `unknown`, e.g. `Type 'unknown' is not assignable to type 'string'`. The agent diagnosed this by checking `npm view zod version && npm ls zod`, updated the dependency, and the next `npx tsc --noEmit` passed. This suggests the SDK’s Standard Schema typing is sensitive to older Zod 4 releases without an immediately actionable compatibility message.

With no skill file available, the agent relied heavily on installed-package inspection: `sed -n '1,220p' node_modules/mcp-use/README.md`, then `server.d.ts`, `resources.d.ts`, `tools.d.ts`, and `config.d.ts`. It also grepped for API shape with `rg -n "listen\\(|securitySchemes|resourceTemplate\\("`. This discovery work found useful details such as `listen(port?: number...)`, but required several node_modules searches rather than a concise obvious example.

Verification had two environment/tooling detours. The formatted tools-list check failed because `/bin/bash: line 1: jq: command not found`, after which the agent reran raw `curl`. The final repository check also failed because `fatal: not a git repository`, caused by chaining `git status --short && ...`, so the intended source grep never ran. Server shutdown was recorded as a failed tool result with `exitCode":130` despite successful lifecycle logs, which is harmless but noisy when a long-running verification process is intentionally interrupted.
