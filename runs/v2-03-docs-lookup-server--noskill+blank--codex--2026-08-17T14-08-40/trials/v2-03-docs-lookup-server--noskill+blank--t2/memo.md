The main discovery cost was learning the SDK API from package artifacts rather than an available skill: the agent queried npm with `npm view mcp-use readme` and then searched installed declarations using `rg -n "resource\\(" node_modules/mcp-use` and `sed -n '1,230p' node_modules/mcp-use/dist/resources.d.ts`. This worked, but required several exploratory calls to establish `resource`, `resourceTemplate`, and `listen` shapes.

TypeScript setup had a small papercut: despite installing `@types/node`, the first `npx tsc --noEmit` failed with `Cannot find name 'process'` and instructed the agent to `add 'node' to the types field in your tsconfig`; modifying `tsconfig.json` resolved it on the next run.

Verification also required extra CLI discovery and another dependency. After a plain GET only established that `/mcp` returned `HTTP/1.1 204 No Content`, the agent ran `./node_modules/.bin/mcp-use --help | head -100 && npm install --save-dev @mcp-use/client`, then consulted three help commands including `mcp-use client connect --help` before successfully exercising the server. The client created workspace state at `.mcp-use/usage.json`, containing `{"schemaVersion":1,"serverId":...}`, which the agent then explicitly deleted.

One combined verification command was marked failed solely because it appended `git status --short` in a blank non-repository workspace; the useful checks had already succeeded, but the command ended with `fatal: not a git repository (or any of the parent directories): .git`. Shutdown also needed a follow-up: immediately after `kill 442 455`, `pgrep` still showed `455 node node_modules/.bin/tsx src/server.ts`, although a later check confirmed it was gone.
