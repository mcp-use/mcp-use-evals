The clearest scaffold papercut was conflicting module configuration: `package.json` contained both `"type": "module"` and `"type": "commonjs"`, causing `TS1309: The current file is a CommonJS module and cannot use 'await' at the top level.` The agent inspected the file, removed the duplicate CommonJS setting, and then `npx tsc --noEmit` succeeded.

SDK discovery was somewhat manual. The agent first queried npm with `npm view mcp-use version description repository.url homepage --json`, then read `node_modules/mcp-use/README.md` and declaration files including `node_modules/mcp-use/dist/server.d.ts`, `config.d.ts`, and `tools.d.ts`. It also grepped declarations for `resourceTemplate|\\.resource\\(`, indicating that the installed package’s types and README—not a skill file—were the primary API references.

Live verification had a process-management stumble. The agent invoked `PORT=3111 npx tsx src/server.ts` twice; the second attempt failed with `Error: listen EADDRINUSE: address already in use 127.0.0.1:3111`. It later found both wrapper and child processes via `pgrep -af 'tsx src/server.ts'` and explicitly killed `526` and `539`.

Client usage also required command-by-command discovery through `npx mcp-use client --help`, `npx mcp-use client docs --help`, and `npx mcp-use client docs resources --help`. One discovery oddity was that `resources list` showed only `"uri": "docs://index"` even though direct template reads such as `resources read docs://authentication` worked and returned the expected body; this can make parameterized resources less visible during manual verification.
