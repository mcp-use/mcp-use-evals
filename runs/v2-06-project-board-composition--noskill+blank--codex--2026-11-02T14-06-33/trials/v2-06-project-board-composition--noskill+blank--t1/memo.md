The main discovery friction was API-shape investigation: the agent first tried npm metadata/readme, but `npm view mcp-use readme` produced an empty file and `SyntaxError: /tmp/mcp-use-readme.json: Unexpected end of JSON input`. It then leaned heavily on installed declarations and package sources, including `sed -n '1,240p' node_modules/mcp-use/dist/server.d.ts` and searches for `"listen\\(|resourceTemplate|new MCPServer"`, rather than a skill file or fetched docs URL.

The initial scaffold caused a module-configuration wrong turn. `npm init -y` created `"type": "commonjs"`, and the edited package later contained both `"type": "module"` and `"type": "commonjs"`, leading to `TS1309: The current file is a CommonJS module and cannot use 'await' at the top level.` Removing the duplicate CommonJS declaration fixed the subsequent `npx tsc --noEmit`.

The SDK’s anonymous-usage behavior was an unexpected papercut for a no-files task: after running the server, the agent found `./.mcp-use/usage.json` containing `{"schemaVersion":1,"serverId":"883e8a14-13f6-4205-8dce-ba02bbbdc017"}`. It deleted the file, grepped SDK internals for `"usage\\.json|usage"`, and added `process.env.MCP_USE_ANONYMIZED_TELEMETRY = "false";` in `src/server.ts` to suppress recreation. This extra investigation consumed several calls even though the issue tracker itself remained in memory.

There were also avoidable environmental-command failures: the agent ran `git status --short` despite the blank directory not being a repository and received `fatal: not a git repository`. Both foreground server runs ended with tool status `exitCode:130` after successful request logs, so the harness represented intentional server termination as `"status":"failed"`, adding noisy apparent failures to otherwise successful lifecycle verification.
