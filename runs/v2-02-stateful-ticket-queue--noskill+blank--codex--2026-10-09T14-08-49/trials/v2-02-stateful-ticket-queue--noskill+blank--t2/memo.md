The main friction was API discovery: the agent first queried npm metadata with `npm view mcp-use version description homepage repository.url --json`, then inspected the installed package via `sed -n '1,260p' node_modules/mcp-use/dist/server.d.ts` and related declaration files. The useful listener behavior came from those typings, including `listen(port?: number | undefined...)` and the note that port precedence is “`the argument, PORT, config.port, then 3000`”; no skill file or external docs URL was used.

The initial TypeScript setup fought `npm init` defaults. The generated package had `"type": "commonjs"`, leading to `TS1309: The current file is a CommonJS module and cannot use 'await' at the top level.` Although `@types/node` had been installed, the first config omitted it and produced `TS2591: Cannot find name 'process'... add 'node' to the types field in your tsconfig.` The agent then changed the package to `"type": "module"` and adjusted `tsconfig.json`, after which `npx tsc --noEmit` passed.

There was also a small wasted cleanup step: the agent ran `git diff --check && git status --short` in a blank non-repository directory and received `warning: Not a git repository.` Verification itself was otherwise direct and comprehensive, with responses such as `Open tickets (2): Cannot reset password, Billing question`, `Ticket 999 not found`, and `Open tickets (1): Billing question`.
