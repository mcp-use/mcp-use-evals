The decisive wrong turn was placing the entry point at repository root: the produced server is `index.ts` with `export default server;`, while the deterministic grader reports `no entry file found (tried: src/server.ts, src/index.ts)`. This was encouraged by the installed SDK README, which said `Replace its \`index.ts\` with a view-bound tool`, and the local build reinforced it with `[mcp-use] built index.ts + views ... → .mcp-use/build/index.js`; the scaffold/docs and evaluation entry convention were therefore misaligned.

The agent leaned heavily on installed-package discovery rather than a skill file: it searched `node_modules/mcp-use/README.md` and declarations using `rg -n "registerTool|registerApp|view|ui://|resource"`, then inspected `use-tool-context.d.ts` and `register.d.ts`. One search included a nonexistent package path and emitted `rg: node_modules/@mcp-use: No such file or directory`, a small discovery papercut.

Typed output handling caused one repair cycle. The first typecheck failed with `error TS2345` because the callback result containing readonly detail data was not assignable to the declared output schema, after which `index.ts` was modified and `npx tsc --noEmit && npx mcp-use build --inline` succeeded.

Runtime verification also had avoidable friction. The first start invocation remained active, so a second produced `listen EADDRINUSE: address already in use 127.0.0.1:3210`; the agent then had to inspect processes with `ps -ef` and later `kill 523 557`. The CLI’s verification commands unexpectedly required another package: `@mcp-use/client is required for this command`, prompting an extra `npm view @mcp-use/client version` and install. The installed client was `2.4.5`, visible in `server/discover mcp-use/2.4.5`, even though the server dependency requested by the task was 2.0.4, which adds version-mixing risk during validation.

A final combined verification command also returned failure solely because it ran Git metadata in a blank directory: `fatal: not a git repository (or any of the parent directories): .git`, despite printing all six checks as `true`.
